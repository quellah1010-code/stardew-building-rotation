# 原型接入与验证

## 当前边界

仓库已有设计记录、通用几何核心、编辑草稿、手势判定器和由外部移动状态驱动的输入入口。尚无 SMAPI 入口、原版/第三方移动状态探测、真实鼠标事件订阅、运行时碰撞补丁、贴图切换、传送或存档写入。独立 C# 编译和 40 组自检已执行；完整项目构建与游戏内测试的边界见下方验证记录。

核心库不引用游戏，让格子变换可以单独验证。自检是一个普通控制台程序，请用 README 的 `dotnet run` 命令执行，不要用 `dotnet test` 将“未发现测试”误认成成功。

## 核心坐标约定

地图格子 X 向右、Y 向下。朝向表示入口朝向：South 是门朝下的正向，East 朝右，North 是门朝上的背向，West 朝左。代码枚举顺序为 South、East、North、West，仅用于循环；不称它为屏幕坐标里的顺时针，也不预先决定鼠标手势映射。

占地原点为当前朝向包围矩形的左上格，不等于贴图左上像素，也不等于最终鼠标抓取锚点。以未旋转宽 W、高 H，局部格子坐标 (x, y) 为基准：

| 朝向 | 占地宽高 | 变换后局部格 |
| --- | --- | --- |
| South | W × H | (x, y) |
| East | H × W | (y, W − 1 − x) |
| North | W × H | (W − 1 − x, H − 1 − y) |
| West | H × W | (H − 1 − y, x) |

`Doorway` 接收已经处于当前朝向的占地和门格，检查门是否位于对应外边缘，计算门外相邻的一格。该结果不是已验证的游戏传送坐标：接入层还要检查地图范围、可通行性、玩家碰撞盒和实际传送偏移。它也不负责多格动物门、Reveal 区或美术像素坐标。

## 编辑与输入接入约定

### 由已有移动模式驱动

不注册本 mod 的全局启动或拿起快捷键。游戏接入层识别已有搬动流程的当前状态，再通过 `MoveModeGesture.Sample` 驱动手势；不能仅凭安装了某个 mod、按下了某个键，或窗口类型为建造菜单就启用。原版流程还需确认处于移动子模式；第三方流程可能完全不创建窗口，需要各自的接入层。

`MoveModeContext` 是接入层提供的不可变状态快照，不是已经实现的游戏状态探测器：

| 字段 | 接入层责任 |
| --- | --- |
| `ProviderId` | 唯一的当前搬动流程，例如原版或某个已适配 mod；不要将多个候选依次送入判定器争抢同一输入 |
| `SessionId` | 当前搬动事务的稳定标识；放置完成、重新拿起、换地图或换存档后更新，即使还是同一栋建筑 |
| `HeldBuildingId` | 当前单栋悬空建筑的稳定标识；无建筑时用 null，不能用鼠标位置或贴图坐标代替身份 |
| `IsMoving` | 当前确实正在执行搬动，不能把建造、升级、拆除或复制模式算作已支持 |
| `SupportsRotation` | 已确认支持当前目标的旋转；尚未适配的类型及批量选择不启用 |
| `OwnsGestureInput` | 已与原搬动流程协调放置/旋转输入，能阻止同一次手势被双方执行；这不是仅观察窗口就能推导出的能力 |

只有上述条件都成立且持有建筑时才启用手势。无可识别的协作流程、流程归属有歧义、失去焦点或不允许编辑时传 null；条件失效与 provider/session/建筑身份改变都会清除旧手势。即使同一窗口没有关闭，也要重新读取实际移动子模式。每帧的新快照只要身份相同就不会重置正在进行的手势。

`Sample` 接收当前快照、物理鼠标按下状态、屏幕坐标和单调真实时间，在鼠标按下/抬起以及每帧更新时调用。目标刚被选中时就应采样，包括拾取事件本身；此时已经按下的鼠标属于拾取操作，必须等抬起后的新按下才能开始编辑。模式刚失效或换目标的采样只清理旧状态，不把原手势转交新建筑。不能只在移动模式内订阅输入而漏掉退出、中断的状态通知。

返回的 `MoveGestureResult.IsHandled` 表示本次输入是否归当前手势处理，`Intent` 表示是否产生操作。长按中的按下、旋转后的抬起可以是 `IsHandled = true` 且 `Intent = None`，接入层仍需阻止原搬动流程对此直接放置。输出 `None` 不能被误读成应当补执行一次原版点击；返回未处理则不由本判定器消费输入。具体如何协调事件顺序与屏蔽原处理尚未实现，也不能依靠在上游已经放置后再抑制输入来补救。

取消、失去焦点、地图/存档切换或当前接入层失效时调用 `MoveModeGesture.Reset()`。该类只清理输入；接入层必须同时丢弃未提交草稿、收尾原搬动流程，并在焦点等条件恢复前继续报告不可编辑。成功放置以后即使仍选中同一建筑，下一次事务也需新草稿和新 `SessionId`。

移动模式条件不用于关闭日常的朝向绘制、碰撞、门与出入口、Reveal 或存档恢复；这些应当读取已提交的建筑朝向独立工作。当前自检只证明输入中断不会改回模拟世界中的已提交朝向，不证明这些游戏系统已经接入。

### 草稿与底层手势

`PlacementDraft` 保存不可变的原位置、原朝向和可更改的预览值，移动与旋转只改预览。`TryPlace` 接收同步回调，回调成功后完成该次放置；失败或抛异常时，草稿仍可修改或取消。回调执行期间拒绝重新编辑或重复提交，防止候选值在提交中途发生变化。

**接入层负责真实建筑写入的原子性。** 回调需要重新检查当前放置是否合法，并完成写入；返回 false 或抛异常前，必须保证游戏状态没有被部分修改。核心类不能替回调回滚游戏对象，独立自检也不证明这个游戏侧事务已经实现。成功的放置不能再由旧草稿取消；若界面继续选中建筑，下一次移动要以刚放好的位置与朝向新建草稿，这不预先决定界面是否退出选中状态。

`EditGesture` 是底层意图识别器，不调用游戏，游戏输入应经过上面的 `MoveModeGesture` 条件控制。输入为屏幕像素坐标和单调递增的真实耗时，不能用可能暂停的游戏时钟；每帧更新一次，即使鼠标没有移动，也要检查长按阈值。向屏幕 X 正/负方向拖动分别产生 `RotatePositive` / `RotateNegative`，具体映射到哪个建筑朝向由接入层决定。松手事件也会检查最终坐标；若旋转已触发，该次松手不再产生放置意图。

| 当前手势原型 | 输出 |
| --- | --- |
| 短按、没有超过移动阈值，然后松手 | 一次 `Place` 意图 |
| 同时满足长按与水平拖动阈值 | 一次旋转意图；之后继续拖动或反向都不会再次旋转 |
| 旋转后松手 | 不放置，建筑继续悬空 |
| 长按不拖动、纵向为主的拖动、快速大幅拖动 | 不放置；这些防误放细节仍待游戏试用 |
| 取消、退出移动模式、地图切换、失去焦点后迟到的松手 | 先重置判定器，松手不产生任何意图 |

拾取建筑的鼠标点击须由原搬动流程消费，不能直接对底层识别器调用 `Begin`；`MoveModeGesture` 会忽略进入选中状态时已按下的鼠标，之后新的按下再开始手势。取消、中断或换选目标时，外层入口清理底层手势，接入层负责处理当前草稿。UI 输入屏蔽、摄像机/缩放、鼠标抓取锚点、世界时间是否暂停，以及所有游戏事件订阅都还没有接入。

## 参考 mod 接入调查

2026-09-08 复核 Let's Move It `develop`，固定观察版本为提交 `a33106cb20df864685cff8675f21282bde24de37`。其 `ModEntry` 用私有 `SingleTarget` 保存单个选中目标，`SelectTargetAction` 可直接在当前地点选中目标，不要求新建移动窗口。因此只监听菜单打开无法覆盖这一流程；需要专门取得其有效选中状态，并协调输入。[源码：ModEntry.cs](https://github.com/Exblosis/StardewValleyMods/blob/a33106cb20df864685cff8675f21282bde24de37/LetsMoveIt/ModEntry.cs)

同一版本的 `OnButtonPressed` 在 `MoveKey.JustPressed()` 后调用 `SingleTargetAction`，后者执行 `MoveTo` 或 `CopyTo`。因此长按旋转的输入必须先区分点击与拖动，再决定是否放置；不能原样保留按下即放置，再追加长按逻辑。读取到选中目标或执行一次 SMAPI 输入抑制都不等于已经解决这个顺序问题。[源码：ModEntry.cs](https://github.com/Exblosis/StardewValleyMods/blob/a33106cb20df864685cff8675f21282bde24de37/LetsMoveIt/ModEntry.cs)

此前查阅的建筑移动实现走 `buildStructure` 路径，施工或升级中的建筑被拒绝；其中还有室内出口更新逻辑。接入真正的四向占地和出口时，需要逐项复核这些行为，不应把原有搬动功能当成已提供了旋转接口。[源码：Move.cs](https://github.com/Exblosis/StardewValleyMods/blob/develop/LetsMoveIt/TargetData/Move.cs)

上述 `ModEntry.cs` 链接已固定版本，其他分支链接仍可能变化，真正接入或引入代码前要固定并记录相应版本，同时检查许可证。本次没有导入上游实现，也没有决定 fork 或独立 mod 路线。原版移动子模式的具体游戏字段尚未在用户游戏版本中核验，不写入猜测的字段绑定。

SMAPI 的 `MenuChanged` 表示菜单打开、关闭或替换；事件参数是事件发生时的快照，未必仍是当前状态。因此它可用作重新检查的提示，不能充当“当前必定在搬建筑”的唯一开关。[SMAPI 事件文档](https://stardewvalleywiki.com/Modding:Modder_Guide/APIs/Events)

SMAPI 后续工程可通过 `Pathoschild.Stardew.ModBuildConfig` 引用游戏与 SMAPI，并配置游戏路径。相关测试若引用游戏程序集，仍需要游戏安装；不要把它们与当前纯几何自检混淆。[SMAPI 构建包文档](https://github.com/Pathoschild/SMAPI/blob/develop/docs/technical/mod-package.md)

## 下一阶段验收顺序

1. 在正常开发环境复核 README 的项目构建/自检命令；确认本机游戏、SMAPI 版本和引用路径，再建立最小游戏入口。当前核心源码的直接编译与独立自检已经完成。
2. 验证原版移动子模式与首个目标搬动 mod 的实际状态识别、输入协调和退出收尾；用单栋无动物测试牛棚及占位图打通拿起、移动、转一档、合法放置、取消，检查原建筑在预览期间不被写坏，且同一次点击不被两个流程重复执行。普通行走、仅打开建造菜单及未知搬动 mod 下不接管旋转。
3. 逐方向验证占地框、实际碰撞、门格及门外通路；重点测试宽高交换后的窄通道、地图边缘和已占用地块。
4. 验证四向进出门，室内保持不变；门外被挡时不能将人物送入建筑碰撞区或地图外。
5. 接入背面专用 Reveal，保证可见门与真实门重合；覆盖进出触发边界、站在门口、远处回看等场景。
6. 保存并重载，检查朝向、贴图、碰撞、传送一致；测试取消、中断和异常恢复后，再扩展动物与升级场景。

接入阶段的原型包需明确标注仅供测试；完成相应游戏内检查后，才能声称对应功能已验证或兼容现有存档。测试游戏功能使用独立存档，且不把存档、日志中的私人信息、游戏 DLL 或解包贴图提交到仓库。
