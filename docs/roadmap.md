## 接进游戏，再用实机完成验证

这部分代码可以先准备；准确引用、补丁位置和最终行为需要本机游戏环境核对。用户回家后提供版本信息并协助操作反馈，代码与美术仍由助手继续完成。

- [ ] **4. 核对环境与真实建筑数据。** 记录游戏、SMAPI 和参考搬动 mod 的版本；读取目标牛棚的实际占地、通行格、门区与贴图信息；完成正常工程构建。游戏程序集和个人存档不放进公开仓库。
  - 已推进：真实 Content 已读取并完成独立映射／验证；见 [content-mapping.md](content-mapping.md)。已核对游戏 1.6.15／Let's Move It 0.6.20，SMAPI 4.5.2 文件已对齐，0.0.2 诊断包 Release 构建／打包完成；待实际加载与最终数据核验，仍需三项游戏附属引用，整项不勾选。
  - 完成标准：确定支持的版本，确认所需接口／补丁目标与实际版本相符，编译出可加载的最小工程。
- [ ] **5. 接入现有建筑移动流程。** 添加 SMAPI 入口与原版移动流程适配，再接第一个确认兼容的便携搬动 mod。识别“正在移动、已拿起哪栋建筑、当前由谁处理鼠标”，协调原搬动功能的点击放下行为。
  - 完成标准：不用新增启动快捷键；拿起时不会误放下；长按拖动只旋转一次，松手仍悬空，之后短点击按原版习惯放下。退出移动模式、切换目标或失焦会清掉未完成手势。未适配的搬动流程不接管。
- [ ] **6. 接通预览、放置与取消。** 将当前朝向用于实际预览、红绿放置框和放置合法性检查；检查地图边界、地形、物件、其他建筑及相关角色限制。失败或中断时处理本次草稿及已经发生的游戏侧修改。
  - 完成标准：合法位置才能放下；非法位置不会改变已放置状态；取消恢复本次拿起前的位置与朝向，不撤销以前已经成功的操作。
- [ ] **7. 接通实际碰撞与人物进出门。** 将当前建筑布局用于通行查询、真实门区、进门触发及室内返回室外的落点；室内布局保持不变。先增加开发用格子／门区显示，方便检查视觉和判定是否一致。
  - 完成标准：四个方向都能走到真实入口、进入同一个室内，并从对应门外返回；旧门不再触发，旧占地不残留阻挡，新阻挡处不能穿过。退出编辑后这些行为继续生效。
- [ ] **8. 接通四向贴图和背面 Reveal。** 按实际画布与锚点装入素材，校准地面位置和前后遮挡；首个牛棚仅背面按真实门附近区域触发分层透明，调节范围、透明度和过渡，避免边界闪烁。
  - 完成标准：画出的门与可交互的门重合；人物、地面不随建筑一起变淡；标识与地面引导清楚且不占格。日常行走时 Reveal 仍有效，不依赖移动模式开启。
- [ ] **9. 保存、读档与首版验收。** 按建筑实例保存朝向，读档时恢复对应布局；验证同类型建筑各自转向、多次搬动、取消和重新进入存档。准备可安装的测试包及操作说明。
  - 完成标准：朝向、贴图、碰撞和门在读档后保持一致。用一栋空牛棚跑完“拿起 → 四向旋转 → 放置／取消 → 绕行 → 进出门 → 保存重进”的完整流程，记录实机结果。

**第一份可玩测试包的边界：** 第 4–7、9 项跑通，配有能辨认方向和真实入口的占位素材。第 8 项完成后，再验收我们想要的正式视觉效果。独立自检通过不等于这两项里程碑已经完成。
