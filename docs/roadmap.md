# 接下来具体做什么

这份清单按依赖顺序安排工作；玩法决定以 [design.md](design.md) 为准，实现与验证边界见 [development.md](development.md)。没有标记完成的项目都仍待实现或验证。

**第一版目标：PC、鼠标键盘、单人，用一栋普通空牛棚完成四向旋转。** 先允许使用占位贴图验证玩法；完整建筑种类、动物和联机随后扩展。现阶段还不是可安装的 mod。

## 已经有的基础

- [x] 独立的四向占地与格子坐标变换、单格边缘门及门外相邻格计算。
- [x] 独立的编辑草稿、放置／取消状态和长按拖动手势。
- [x] 根据外部移动状态启停手势的入口；能隔离不同建筑、会话和输入所有者。实际游戏状态识别尚未接入。
- [x] 当前 40 项独立自检通过。使用 Roslyn 直接编译并执行；标准项目构建及游戏内测试仍待验证。
- [x] 调查参考搬动 mod、建筑通行数据与人物／动物寻路相关实现。调查使用的游戏代码快照尚未与本机版本核对。
- [x] 探索侧视图和背面 Reveal 概念图。它们还不是对齐实际尺寸、可以直接装进游戏的四向素材。

## 现在可以推进，不必等家里的电脑

- [ ] **1. 补完整的建筑布局计算。** 在矩形占地之外，加入逐格阻挡／通行分布和反向坐标查询；确定旋转时抓取点与建筑原点的关系。每栋建筑保留自己的朝向，读取共同的原始定义，不改全局同类型数据。
  - 完成标准：不对称的阻挡分布能正确转向；四次旋转回到原样；侧向宽高互换；两栋同类型建筑互不影响。这里使用测试数据，不能把测试尺寸当成真实牛棚尺寸。
- [ ] **2. 补门和门外区域计算。** 从现有单格门扩展到多格门、门前净空和占地外的附加区域；用入口朝向计算向外方向。预留逐朝向美术锚点，使重构后的门能与交互位置对齐。
  - 完成标准：四向的门区和通道都落在正确一侧；覆盖非正方形建筑和占地外区域。人物脚部落点用明确的角色尺寸参数计算，最终数值与触发方式仍需游戏验证。
- [ ] **3. 整理第一栋建筑的美术方案。** 统一四向视角和比例；背面拆出可淡化的屋顶／上墙、仍可辨认的墙脚／轮廓，以及清晰的真实门口。门框标识和木板／石子引导纳入建筑绘制，不新增占位物件。
  - 完成标准：明确各层的职责和锚点，并准备可供接入的草稿。读取真实贴图与占地尺寸后，再完成原生像素尺寸、透明背景和最终对齐。

## 接进游戏，再用实机完成验证

这部分代码可以先准备；准确引用、补丁位置和最终行为需要本机游戏环境核对。用户回家后提供版本信息并协助操作反馈，代码与美术仍由助手继续完成。

- [ ] **4. 核对环境与真实建筑数据。** 记录游戏、SMAPI 和参考搬动 mod 的版本；读取目标牛棚的实际占地、通行格、门区与贴图信息；完成正常工程构建。游戏程序集和个人存档不放进公开仓库。
  - 完成标准：确定支持的版本，确认所需接口／补丁目标与实际版本相符，编译出可加载的最小工程。
- [ ] **5. 接入现有建筑移动流程。** 添加 SMAPI 入口与原版移动流程适配，再接第一个确认兼容的便携搬动 mod。识别“正在移动、已拿起哪栋建筑、当前由谁处理鼠标”，协调原搬动功能的点击放下行为。
  - 完成标准：不用新增启动快捷键；拿起时不会误放下；长按拖动只旋转一次，松手仍悬空，之后短点击按原版习惯放下。退出移动模式、切换目标或失焦会清掉未完成手势。未适配的搬动流程不接管。
- [ ] **6. 接通预览、放置与取消。** 将当前朝向用于实际预览、红绿放置框和放置合法性检查；检查地图边界、地形、物件、其他建筑及相关角色限制。失败或中断时处理本次草稿及已经发生的游戏侧修改。
  - 完成标准：合法位置才能放下；非法位置不会改变已放置状态；取消恢复本次拿起前的位置与朝向，不撤销以前已经成功的操作。
- [ ] **7. 接通实际碰撞与人物进出门。** 将当前建筑布局用于通行查询、真实门区、进门触发及室内返回室外的落点；室内布局保持不变。先增加开发用格子／门区显示，方便检查视觉和判定是否一致。
  - 完成标准：四个方向都能走到真实入口、进入同一个室内，并从对应门外返回；旧门不再触发，旧占地不残留阻挡，新阻挡处不能穿过。退出编辑后这些行为继续生效。
- [ ] **8. 接通四向贴图和背面 Reveal。** 按实际画布与锚点装入素材，校准地面位置和前后遮挡；仅背面按真实门附近区域触发分层透明，调节范围、透明度和过渡，避免边界闪烁。
  - 完成标准：画出的门与可交互的门重合；人物、地面不随建筑一起变淡；标识与地面引导清楚且不占格。日常行走时 Reveal 仍有效，不依赖移动模式开启。
- [ ] **9. 保存、读档与首版验收。** 按建筑实例保存朝向，读档时恢复对应布局；验证同类型建筑各自转向、多次搬动、取消和重新进入存档。准备可安装的测试包及操作说明。
  - 完成标准：朝向、贴图、碰撞和门在读档后保持一致。用一栋空牛棚跑完“拿起 → 四向旋转 → 放置／取消 → 绕行 → 进出门 → 保存重进”的完整流程，记录实机结果。

**第一份可玩测试包的边界：** 第 4–7、9 项跑通，配有能辨认方向和真实入口的占位素材。第 8 项完成后，再验收我们想要的正式视觉效果。独立自检通过不等于这两项里程碑已经完成。

## 空牛棚闭环之后

- [ ] **10. 适配动物与 NPC。** 分别核对动物门、门外检测区域、出门位置／初始方向和回家目标，保留原有时间、天气等条件；再核对 NPC 使用的寻路入口与旧路径处理。不能假定只换门坐标就够，也不能假定所有角色共用一条寻路逻辑。
  - 完成标准：在实际支持版本中验证动物四向出入、回家和门前受阻的行为；NPC 按具体场景验证，不以玩家能走通代替。
- [ ] **11. 扩展与发布准备。** 逐类适配建筑升级和特殊交互、其他外观／搬动 mod；之后再扩展手柄、多人同步与完整建筑素材。确定分发路线和许可证，并设计可验证的停用／恢复流程。
  - 完成标准：维护明确的支持范围与已知限制；每增加一种建筑或兼容对象都有对应实机记录。不能承诺卸载后会自动恢复且没有位置冲突。

**下一项优先工作是第 1 项，再接第 2 项。** 它们决定“哪里挡路、门在哪里”，也给后续画图提供对齐依据。手势阈值、旋转抓取锚点和 Reveal 参数先保留为可调整项，实机体验后再定。
