# 空牛棚旋转实验版 0.1.5

**0.1.5 替换被用户否决的朝东素材，改用完整重画的 v2 侧面。** 新图 92×112，地面原点为 (14,0)，墙脚对应原来的 64×112／4×7 格占地，屋檐允许伸出；人门世界坐标保持不变。已做人物、原版牛棚与旧稿的同尺度离线对照。新图仍待游戏内美术反馈，其他已接管方向继续用占位图。输入、碰撞、门与存档代码未改。

## 安装与操作

1. 完全退出游戏，用 ZIP 内的 `BuildingRotation.Prototype` 替换旧的同名 mod 文件夹。若还留着 `Mods/BuildingRotation.Diagnostics`，也移除该旧 mod 文件夹；UniqueID 相同，不能同时安装。保留 Let's Move It。已有测试档和普通牛棚可继续使用。
2. 通过 SMAPI 启动，日志应显示 `Building Rotation — Prototype 0.1.5`。`br_status` 的状态应包含 `rebuilt east-facing sprite v2`。如果提示 `East Barn art could not load`，检查替换时是否连同 `assets` 子文件夹一起复制；若有红色错误，反馈该段日志。
3. 进入单人测试存档，使用 **普通 Barn**：未升级、未施工、没有动物居住，除默认固定取草槽外没有放入物品、家具或角色。取草槽无需拆除。Big Barn／Deluxe Barn 不进入旋转模式；它们仍可按原搬动 mod 移动。当前实际接入版本为游戏 1.6.15、SMAPI 4.5.2、Let's Move It 0.6.20。
4. 按平时的 Let's Move It 操作拿起建筑（默认 Alt＋左键），拿起后松开 Alt。需单选、关闭复制／多选，原搬动键保持单独的左键；不新增启动快捷键。
5. 按住**右键**约 **0.35 秒**，向左或右拖动至少约 24 屏幕像素，旋转一档。一次按住最多转一档；右键短点、长按不动和松手都不会放下。**左键点击立即尝试放置**，也可以不旋转直接放下。鼠标抓住的那格继续贴着鼠标。
6. 原搬动 mod 的取消键（默认 Esc）取消预览；失焦、换地点、失去选择或保存前也会丢弃未提交预览。已经成功放下的建筑位置和朝向会保留。

右键只在已进入旋转预览时用于旋转，普通行走／未选择建筑时保持原用途。如果自己的 Let's Move It 配置已将右键用于取消、删除或其他快捷键，会报告具体冲突，不擅自修改原配置。

绿色框表示当前检查允许放置，红框表示被地形、物件、角色或门前空间挡住；最终点击时还会重新检查。本版要求地面清理好，不自动删草、作物、物件或挖掘点。人物自己也不能站在候选占地或门外检查区域里。

朝东放下后会显示瓦顶、红墙和右边缘的窄门框，外侧青框是门前区域；站到青框内面朝左，按正常交互方式进门。其他已接管朝向仍使用金棕色格子占位，实心青格标记人门。房间内部保持原样，出门回到当前朝向的门外；门外被堵时应拒绝出门。原本未旋转的普通牛棚仍由游戏绘制。

## 这轮看什么

继续用现有“旋转测试”档及已经保存的牛棚，不需要再建副本。换包后 `br_status` 应显示 0.1.5。

1. 转到 **East／朝东**，拿起和放下后应显示同一张较短、带完整屋檐与墙脚的新图。先看随本轮交付的离线同尺度对照，再判断实际农场里的宽高与画风。
2. 在右侧青框附近走动并进出一次，看窄门框是否对得上实际入口、人物是否被屋顶或墙挡得难以操作。拍一张带人物及旁边原版建筑的图，方便判断宽高和比例。
3. 拿起已朝东的牛棚移开，再按 Esc：图片应回到原位置，旧位置不应残留第二张图。这只检查新贴图的绘制路径。

普通空牛棚的输入、碰撞、进出门和存档代码未改，本轮不重复全部测试。`br_status` 的 `active=False` 在没有拿起建筑时正常，`Save loaded: False` 在载入前正常；这些状态本身不是报错。若有实际错误，贴对应错误段。

这版不支持动物、升级、联机、其他建筑或跨地点搬移，也没有 Reveal、动物门动画或建筑皮肤适配。测试期间保持该牛棚为空，不给它安排动物或升级。其他搬动功能继续由 Let's Move It 处理；已旋转的牛棚在不满足本包编辑条件时会阻止原搬动提交。

## 接入和验证记录

- 0.1.5 用匹配引用完成 Release 构建。RGBA／二值 alpha、墙脚 64 像素宽，以及新旧画布换算后同为 (64,88) 的局部门槛已核对；离线对照检查了屋顶、墙脚和真实占地。仍按建筑底边／SortTileOffset 排序，未实现分层遮挡。0.1.4 虽能显示，但其美术被用户明确否决，不记作素材验收通过。
- 0.1.2 已使用匹配引用完成 Release 构建，**104/104 独立检查通过**。更新运行层测试，验证右键点击／松手不放置、独立提交一次、非法位置保留预览、取消与换选后的迟到输入。这不模拟 SMAPI 事件，也不代替游戏内操作验证。补丁目标未改，未重复签名审计。

- `GameRotationHost` 从真实 `Building.GetData()` 读取碰撞和门区，复用 Data／Core 的不可变映射。实例按对象身份登记，位置、尺寸、门、元数据、房间身份及出口变化使快照修订号更新。
- 预览不改游戏建筑。放置时在候选格上调用原版 `isBuildable`，用仅当前调用有效的补丁上下文排除本建筑旧占地；检查地图范围、物件、地形、角色、额外区域和门前净空。不调用会清除世界物件的原版建造流程，也不改变共享建筑数据。
- 提交只写当前建筑的位置、宽高、人门／动物门坐标、自己的 `modData` 朝向键和室内返回 warp。出现异常时尝试恢复所有已记录字段，回滚异常会明确报告。动物门坐标同步不代表动物行为已适配。
- Harmony 在 Let's Move It 的按下即放置方法执行前取得输入控制，原渲染预览在本会话中停止，RotationEditor 只采样右键旋转，左键在该放置入口显式提交。右键的按下／松开通过 SMAPI 事件及时采样并抑制原游戏交互；不会仅靠下一帧采样屏蔽首次按下。取消通过原选择清除流程同步。
- 对已标记的普通 Barn 接入逐格通行、完整矩形碰撞、人门接近方向和占位绘制；加载建筑数据、重建房间或更新出口后重新应用布局。使用游戏原有 `Building.modData` 存储朝向，游戏原有字段保存位置。
- 室外返回在原传送执行前检查落点，完成场景切换后按人物真实碰撞框再次核对并校准像素位置和朝向；若淡入期间出口被占用，尝试返回原房间的标准入口。正常进门保留原来的坐骑／锁定／声音等逻辑。
- 历史接入审计：`BuildingRotation.GameAudit` 直接读取实际 DLL 元数据，**13/13 补丁目标签名符合**。后续用户已确认基本旋转、放置／拒绝／取消、绕行、四向进出门及过夜／载入后交互正常；这不等于完整多实例、异常回滚或兼容矩阵验收。

仍需重点留意输入事件顺序、渲染批次、进出门落点及其他 mod 的影响；检测到兼容问题时按日志修复，不以“签名存在”代替行为验证。当前普通空牛棚的同地点移动只做必要字段更新，不调用可能清除地图内容的放置回调；第三方依赖这些回调的行为尚未验证。

开发复现：

```sh
dotnet build src/BuildingRotation.Smapi/BuildingRotation.Smapi.csproj -c Release -p:GamePath="/path/to/game"
dotnet run --project tools/BuildingRotation.GameAudit -- "/path/to/game" "/path/to/LetsMoveIt.dll"
python scripts/package-diagnostics.py
```

包中仅包含四个自有 DLL、manifest、本说明和 `assets/barn-east-v2.png`，共七个文件；游戏、SMAPI、Harmony、Let's Move It 的 DLL、用户截图和反编译源码均不发布。素材由 imagegen 参考 Barn v6 结构与原版配色完整重画，再作源像素及门位校准，处理方法及预览见 [朝东素材记录](https://github.com/quellah1010-code/stardew-building-rotation/blob/main/docs/art/runtime/README.md)。
