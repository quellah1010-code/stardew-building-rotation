# 建筑旋转：玩法规则

本文记录这次讨论的设计基线，不是功能已实现清单。后续修改以明确的新决定为准，不能把工程建议写成玩家已经确认的规则。

## 已确认的产品方向

玩家沿用已有的建筑搬动入口；配合已适配的便携搬动 mod 时，可以不去 Robin 那里。旋转功能不新增全局启动或拿起快捷键，而是检测是否已经进入建筑移动模式。具体可操作情境沿用所接入搬动流程的合理限制，不把“随时”解释成过场、无关菜单、载入中也强制可用。参考 mod 为 Let's Move It。

“建筑移动模式”指搬动状态，不要求一定弹出一个新窗口：可以由原版搬建筑流程或已适配的搬动 mod 提供。仅打开建造菜单不够，必须处于搬动功能；拿起受支持的建筑后，才识别旋转手势。进入移动模式但还没拿起建筑时待命，退出模式、换选目标或中断后结束当前手势，不把迟到的松手当成放置。进入模式和拿起建筑的原有操作保留。

上述条件只控制编辑与输入接管。平时走路时，已放置建筑的四向外观、碰撞、真实门、出入口落点和背面 Reveal 必须继续工作，不能因退出移动模式而停用或恢复原朝向。取消尚未放下的预览仍按原位置与原朝向恢复。

建筑处于拿起、悬空状态时再旋转，操作方向是长按鼠标拖动。放置、取消尽量沿用原版式体验；不额外加入 Enter 提交整场编辑，也没有新设的 Space 功能。一次成功放置就是该次操作生效，不等于立刻触发游戏磁盘存档。

四向变化包含外部贴图、实际占地格、红绿放置预览、碰撞与外部门的位置。不能做成“图转了，碰撞还是原来那块”。长方形占地转到侧向时交换宽高。室内地图、布局及室内入口位置不随外部旋转；离开室内时，需要回到当前外部门外的正确位置。

仅背向镜头的朝向使用 Reveal：玩家接近入口附近的触发区后，切换到专门重构的、降低透明度的入口展示图。Reveal 区域只负责显示，不是扩大后的进门传送区。显出来的门必须与真实可交互的门对应，不能要求玩家忽略画面上那扇门。

Reveal 不是把原正面图直接拿来半透明盖上去。原正面图中的门在下方，背面实际门在上方，因此要为背向入口重构画面，并校准锚点、透视与门位置。其他朝向不借用背面 Reveal 规则。

Reveal 已选用按结构分层的透明度方案：屋顶和遮挡人物的上部墙体更淡，墙根、基座与占地轮廓保留更强的可见度，真实入口的门框、门槛和附着标识单独保持清楚。入口处的轮廓要对应实际通路，人物和地面不跟随建筑一起变淡；透明度不改变碰撞。具体数值、遮罩和人物前后遮挡需在游戏内校准。已生成的背面对照图仅用于视觉讨论，尚不是拆分好的运行时素材。

入口引导还包括建筑自带的木板、石子等地面视觉元素，不占格，不额外形成碰撞。标识画在建筑、门或门框上，作为贴图的一部分，不再立一个独立占位的实体牌子。具体位置随最终美术重构确定。

先拿一栋建筑试水，不代表最终只想做这一栋；长远目标可以扩到更多建筑，不能反过来要求先画完全套美术才开始验证。

## 首轮工程切片

先验证 PC、键鼠、单人场景下的普通牛棚。用专用测试存档和没有动物的测试建筑，暂不声称支持所有牛棚升级、动物寻路、联机、手柄或其他建筑。以简单占位图验证坐标，不提前投入成套精修美术。

当前实现包括通用几何计算、独立编辑草稿和由外部移动状态驱动的鼠标手势判定，不创建游戏建筑，也不直接修改游戏状态。移动状态目前由自检模拟，尚没有读取原版或第三方 mod 状态的接入层。代码中的 7×4 是测试样例，不是未经核验就写死的当前游戏牛棚数据；接入时应读取并核验目标建筑数据。

## 工程建议，尚不是完整输入实现

短点击用于尝试放置；长按拖动用于离散的 90° 转向。建议每次旋转手势只转一档，松开该次手势后继续悬空，避免旋转结束时误放下。具体左右拖动对应哪一档、手势能否在同次长按内连续转多档，待交互原型确认。

独立手势原型暂按每次按住只触发一次旋转实现，旋转后的抬起事件不放置。长按不移动、纵向为主的拖动，以及快速拖出阈值再拖回的操作也不触发放置。这些是待游戏试用的防误放规则；长按时长与移动阈值必须由调用方传入，自检中的 250 毫秒和 8 像素不是最终默认值。拾取建筑的那次点击只用于拾取，后续一次新的按下才开始识别放置或旋转。

预览使用独立草稿，只有放置合法后才改动真实建筑。取消丢弃当前草稿，保持原位置与原朝向，不撤销之前已经完成的其他放置。非法位置不能靠放置操作覆盖已有物体。

兼容接入时，一次手势只交给一个已确认的搬动流程处理。识别到移动状态还不够，必须协调其原有放置时机；未适配、无法确定唯一操作者或未协调输入的流程不接管旋转。不能因为取消了独立快捷键，就声称自动兼容所有移动建筑 mod。

门、碰撞、放置框和贴图应读取同一份当前朝向布局。矩形变换可以生成初始坐标，但美术重构后的门允许按朝向显式定义，不能要求所有门永远机械地套同一条变换公式。

建筑占地矩形与实际阻挡格需分别处理：范围内的可走缺口也要随朝向转换，门前额外净空和出门方向需要同步。人物碰撞框与农场底图不随建筑旋转；玩家能走通也不直接证明 NPC 或动物会正确寻路。原版数据字段与版本受限的实现观察见[碰撞与寻路调查](collision-and-pathfinding.md)。

## 待定与待验证

| 项目 | 尚缺的决定或验证 |
| --- | --- |
| 输入参数 | 不另设启动或拿起快捷键；取消操作沿用接入的搬动流程。长按毫秒数、拖动像素阈值与左右映射待定 |
| Reveal | 分层方案已确定；触发范围的距离与形状、检测参考点、各层透明度、淡入淡出与防边界闪烁仍待验证，当前代码未硬编码这些数值 |
| 旋转锚点 | 拿起时鼠标抓取点如何随宽高变化、旋转时是否需要补偿位置，确保建筑不跳位 |
| 各向入口 | 人物门的格子与交互范围、出门落点、动物门的宽度和开关状态、门前实际通路 |
| 阻挡与中断 | 门外被挡、地图边界、人物或动物占位、打开菜单、切换地图、存档载入时如何安全收尾 |
| 持久化 | 保存朝向、读档恢复布局、未知数据版本、禁用或卸载 mod 后的恢复方案 |
| 动物与升级 | 动物寻路与回家、升级施工前后数据与美术切换；首轮无动物验证不等于已解决 |
| 兼容路线 | 原版搬动子模式和具体第三方 mod 的状态识别、输入协调与版本范围；修改 Let's Move It 还是通过独立接入层实现仍待验证 |
| 本机环境 | 星露谷版本、SMAPI 版本、游戏路径和当前 mod 列表尚未在开发环境核实 |

全套补丁阶段还要单独评估不同建筑的特殊行为，不能仅替换四张图就宣称通用兼容。
